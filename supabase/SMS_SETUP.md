# Profi.UZ — регистрация по SMS (+998)

## Что уже в GitHub
- `index.html`: форма +998 и ввод 6-значного OTP.
- `sms-auth.js`: `supabase.auth.signInWithOtp({phone})` и `verifyOtp({phone,token,type:'sms'})`.
- Email-вход оставлен как резервный.
- **Отправка настоящих SMS ещё НЕ подключена**: необходимо настроить провайдера и Send SMS Hook. Не вводите секретные ключи в GitHub или клиентский JS.

## Провайдер
Кандидат для Узбекистана: **Eskiz.uz** (https://eskiz.uz). До подключения уточните тариф OTP, договор/юрлицо, имя отправителя, шаблон, API и доставку на Uzmobile/Ucell/Beeline/Mobiuz.

Альтернативы: **DevSMS** (https://devsms.uz), **USMS** (https://usms.uz). USMS документирует отправку через шаблон `POST /api/v1/send` с API-секретом.

## Что настроить в Supabase
1. Dashboard → Authentication → Providers → **Phone**: включить телефонный вход.
2. Dashboard → Authentication → Hooks → **Send SMS**: подключить HTTPS endpoint серверного адаптера Eskiz, который принимает подписанный вызов Supabase, проверяет подпись, получает `user.phone` и `sms.otp`, отправляет код через Eskiz API и возвращает HTTP 200 только после принятия SMS провайдером.
3. В endpoint/Edge Function хранить секреты Eskiz и подписи hook в **Supabase Edge Function Secrets**, не в JS/репозитории. Не логировать OTP.
4. Настроить CAPTCHA, OTP rate limits, ограничения бюджета, разрешённые номера +998, шаблон SMS, мониторинг доставки.
5. Тестировать на двух разных номерах. До включения провайдера SMS не отправится.
6. Опционально в Auth → Phone добавить test phone numbers с фиксированным кодом для разработки; **не использовать реальные номера как тестовые в production**.

## Важно про существующие email-аккаунты
Вход по телефону создаёт отдельного пользователя Supabase, если телефон не связан с email-аккаунтом. Для объединения аккаунтов потребуется отдельная безопасная процедура подтверждения телефона и миграции связей; автоматически объединять аккаунты нельзя.
